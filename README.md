# MYPAGE · 王释贤的个人主页

一个纯静态的个人主页。无框架、无构建工具、无依赖——**双击 `index.html` 就能打开**。

> 目前处于 V2 阶段（视觉打磨 + 内容升级）。V3 计划：反馈表单 + 后台数据库 + 部署上线。

---

## 这是什么

先给同学朋友看，将来给 HR / 面试官看。所以它不只是「一页介绍」，而是尽量让**每条声明后面都跟着证据**：

- 说「在做项目」→ 就给出项目条目、版本线、提交历史
- 说「关注脑机接口 × AI」→ 就给出方向卡片
- 说「会写前端」→ 这个页面本身就是证据（自己写的设计系统，见 `DESIGN-SYSTEM.md`）

## 技术栈

| | |
|---|---|
| 形态 | 纯静态三文件：`index.html` + `style.css` + `script.js` |
| 框架 | 无。不用 React / Vue / Tailwind，不用 npm 与打包器 |
| 字体 | 系统字体（PingFang SC / 微软雅黑），不加载外部字体 |
| 第三方 | 无 CDN、无追踪脚本。页面数据不联网上传 |
| 浏览器要求 | 现代浏览器；关闭 JS 或开启「减少动效」时内容仍可正常阅读 |

## 本地预览

**先分清两件事**：页面本身是纯静态（双击就能看），但「分身有没有大脑」取决于**有没有服务在跑**。

| 你想看什么 | 怎么做 | 分身用什么回答 |
| --- | --- | --- |
| 只看页面 | 双击 `index.html`，或 `python -m http.server 8000` | **本地知识库**（地板，永远可用） |
| 页面 + **云端大脑** | `node server.js` → 打开 `http://localhost:8080/` | DeepSeek（走 `server.js` 那层代理） |
| 页面 + **本机模型** | 先启动 ollama，再按上面任一种打开 | `deepseek-r1:7b`（免费，但慢） |

```bash
# 起服务（＝页面 + 云端大脑）。在项目目录里：
node server.js
# 如果 node 不在你的 PATH 里，用绝对路径：
#   "C:\Users\wshix\.workbuddy\binaries\node\versions\22.22.2-3\node.exe" server.js
# 然后打开 http://localhost:8080/
```

> ⚠️ **`node server.js` 是个前台进程**：**这个窗口一关、或按 Ctrl+C，服务就没了**
> —— 页面照样能打开，但分身会落回本地知识库（不会白屏、也不会报错，只是不那么"聪明"了）。
> 想让别人也能用、而不用你的电脑一直开着 ⇒ 见 **[`DEPLOY.md`](DEPLOY.md)**。

## 数字分身：三条路，掉线自动降级

聊天区背后按顺序挑一个「大脑」，任何一条不通就往下落：

| | 是什么 | 什么时候走 |
| --- | --- | --- |
| ① **显式地址**（`CHAT_BACKEND.url`） | 你手动指定的 OpenAI 兼容端点（将来的 WeClone 微调分身、或地址栏 `?chat=` 临时覆盖） | 配了就走，优先级最高 |
| ② **本机 ollama** | 跑在这台电脑上的 `deepseek-r1:7b` | **只有本机打开时**（`file://` / `localhost` / `127.0.0.1`）—— 免费、最快 |
| ③ **云端代理**（`cloudUrl = /api/chat`） | 部署后的 `server.js`，由它在服务端保管 DeepSeek 的 key 并锁死人设 | **公网访客走这条** —— 不需要你的电脑开着 |
| ④ **本地知识库**（`script.js` 的 `KNOWLEDGE`） | 几条关键词匹配的固定回答，跑在浏览器里 | **地板**：0 依赖、0 延迟、**永远可用** |

①②③ 任何一个出问题（超时 / 非 200 / 坏 JSON / 空回复 / 被跨域拦）⇒ **自动落到 ④**，
并在气泡下加一个「离线版回答」的小标记（如实说明这句不是分身本体答的）。
连续失败 2 次还会**跳闸 2 分钟** —— 否则后端一挂，访客每问一句都要干等。

> ⚠️ **公网解析出来的地址里绝不会出现本机地址** —— 公网页面绝不会去连访客自己的电脑。
> 有一条专门的回归测试守着这条底线（`tools/test-chat-backend.js` 第 9.3 节）。

> ⚠️ 对话区**没有预设问题按钮**（2026-09-23 用户定：只留一个对话框，访客自己问）。
> 引导靠开场白那句话；别顺手把按钮加回来。

### 它「知道什么」是生成出来的：事实档

分身知道的事**只有一份源头**：`data/persona.json`。

| | |
| --- | --- |
| **改一件事怎么做** | 改 `data/persona.json` → 跑 `python tools/build-persona.py` → 两处人设 + 离线知识库一起更新 |
| **为什么这么做** | 人设原来手写在两个文件里（`script.js` 本机用 / `server.js` 公网用），人工同步必然漂移；现在是同一个源编出来的，`--check` 一口就能查出漂移 |
| **它是什么** | `facts`：它能说的事实（会进模型的前提词）。`about`：访客可能怎么问 + 离线兜底怎么答（关键词条目） |
| **⚠️ 别在别处另写事实** | 生成区间（`persona:begin/end`、`kb:begin/end`）里的内容都是生成物，手改会被下一次生成覆盖 |
| **这算「训练」吗** | 算 —— 但**不是重训模型**：微调教的是语气、事实反而更容易记错（见 `WECLONE.md`）。让分身「准确、自然地答」，靠事实档 + 提示词就够，而且改一句立刻生效 |

> 检查是否与事实档一致：`python tools/build-persona.py --check`（0 处需要更新 = 一致）。

### 云端那一层两个开关（都在 `server.js`，默认值已调好）

| | |
| --- | --- |
| **关掉思考模式** | `deepseek-flash` 官方默认**开** thinking（档位 high）。对闲聊分身三处不划算：思考**占同一份 `max_tokens`**（实测会撞 400 上限把回答截断）、输出 token 75→48、**且 thinking 模式下 `temperature` 被官方忽略**（关掉才生效）。改回：`THINKING=enabled` |
| **余额护栏** | key **不能设额度上限** ⇒ 余额低于 `BALANCE_MIN`（默认 ¥1）时代理返回 503，页面自动落回知识库。⚠️ **查不到余额时不拦**（宁可晚一点降级，也不让临时故障把分身停摆） |

### 回答是流式的：字边生成边出现（2026-09-23 加）

以前是「整段答完再一次性冒出来」——秒级空等（本机推理模型更久），体感像卡住。
现在**首字先到就先显示**，后面的字随生成随上屏。

| | |
| --- | --- |
| **怎么开的** | 页面问分身时带 `stream: true`，代理把上游的 SSE **原样透传**（不攒成一整包）|
| **花不花钱** | 输出 token 数**一模一样**（只是分批发）—— 不额外花钱 |
| **端点不认流式** | 会回整包 JSON ⇒ 页面按 `content-type` 分流，照样能答（`?chat=` 指向任意端点时的关键容错）|
| **半路断了** | 已经收到的字**照常留在屏上**（不吞掉访客看过的内容）；一个候选都没成，才撤掉那半句、落回知识库 |
| **撞到输出上限** | 上游 `finish_reason = length` ⇒ 气泡下多一句「被截断」小字条，而不是让访客对着没说完的话猜 |

> 回归测试：`tools/test-chat-backend.js` 第 12 节（半行拼回 / 心跳与坏行跳过 / 截断标记）、
> `tools/test-chat-proxy.js` 第 11 节（代理原样透传 SSE，连 `[DONE]` 都在）。

### 记忆：只存在访客自己的浏览器里

刷新页面或下次再来，**上次聊的内容还在** —— 数据存在访客自己浏览器的 `localStorage` 里，
**不进服务端、不落库**。聊天窗里会有一条分隔线写明这一点，标题栏右侧有个「清空记忆」。

| | |
| --- | --- |
| **存什么** | ① 访客看得见的对话（用来把界面铺回去）② 要带回模型的那几轮（`ctx`）|
| **不存什么** | **人设、配置、key 一律不存** —— 有一条回归测试专门盯着这点（`tools/test-chat-memory.js` 第 3 节）|
| **为什么不存服务端** | 页面是公开的：一旦把所有人的对话存到一处，**访客 A 说过的事可能被访客 B 问出来**。存本机没有这个问题 |
| **拿不到存储时** | 隐私模式 / 配额满 / 被策略禁用 ⇒ **静默退化成「不记忆」**，聊天照常（不会因为这个功能把页面弄坏）|

> ⚠️ `ctx` 会被送进模型 ⇒ 在写入时就卡死形状（**只收 `user` / `assistant` 的纯文本**）。
> 这不只是洁癖：`localStorage` 里的内容**访客自己就能改**，所以这里是一道本地防线，
> 而服务端还有第二道（它也会丢掉客户端的 `system`）—— 两边都不指望对方。

### 本机开发：用本地模型（0 元）

装了 [ollama](https://ollama.com) 就行 —— 页面在**本机打开时会自动接上它**。

```bash
ollama list                 # 现在装的是 deepseek-r1:7b
python -m http.server 8000  # 推荐这么打开（跟部署后访客的形态一致）
# 打开 http://localhost:8000/
```

> ⚠️ **双击 `index.html` 也能用了**（2026-09-23 修）：`file://` 页面上本机 ollama 一定回 403
> （它发的 `Origin` 是 `null`，不在 ollama 默认白名单里），但页面现在会**自动落到云端代理**
> —— 前提是 `server.js` 在跑、端口跟 `localCloudBase` 对得上。
> **以前这种情况会直接掉进知识库**，看起来就像「没接上」—— 那正是这条修复要解决的问题。
> 不过仍然**推荐用 `http://localhost:8000/`**：那才是部署后访客的真实形态（同源、没有跨域）。

⚠️ 本机模型是 **`deepseek-r1:7b`** —— 它是**推理模型**，答一句要 2.5~6.2 秒（冷启动 ~10 秒），
所以 `CHAT_BACKEND.timeoutMs` 是 **20000**（不再是默认的 8000）。
想换模型就在地址栏加 `?model=`（名字照 `ollama list` 写），不用改文件。

## 设计上几个刻意的决定

- **全站只有 6 个颜色**（`--c-ink / --c-muted / --c-brand / --c-mint / --c-bg / --c-surface`）。
  层次靠一条透明度派生通道 `--c-brand-rgb` 做，不新建色阶。想加颜色前先问「能不能用透明度派生」
- **渐变只往暗里走**。往亮走会让白字对比度掉到 2.5:1（低于 WCAG AA 的 4.5:1）
- **文字用逐行入场，容器用整块淡入**。逐行是 JS 按渲染后的实际换行拆的，不是硬编码
- **尊重 `prefers-reduced-motion`**。用 `animation-duration: .01ms` 而不是 `animation: none`
  —— 后者会让 `fill-mode: both` 的动画卡在 `opacity: 0`，内容直接消失
- **易过时的数字交给脚本，不靠人记**。页面上那句「共 N 次提交」今天手工改过 4 次——
  每提交一次它就过时一次。现在由 `tools/sync-version.py` 从 `git rev-list --count` 读出来写回，
  提交前跑一次即可。它会把**正在准备的这一次**也算上：数字描述的是「提交之后」的状态，
  不加一的话提交完立刻就差 1
- **首屏那个玻璃泡泡是「按机制重做」，不是抄来的**。灵感来自 CodePen 上的一个 pen，
  但它的源码抓不到，所以这里是从机制自己搭的：环形文字用 SVG `textPath` 挂在整圆上匀速转；
  玻璃用「圆形裁切 + 高光边 + SVG 位移滤镜做**边缘**折射」。
  **滤镜只加在静态图片层、不加在旋转文字上**——挂在旋转元素上会变成每帧逐像素重算。

## 无障碍

- 小字号（≤12px）用 `--color-muted` 或 `--color-brand`，两种主题下都过 WCAG AA
  （实测：次要灰 **浅色 7.27:1 / 深色 9.45:1**；强调青 **浅色 5.47:1 / 深色 12.80:1**）
- 装饰性元素（Marquee 横幅、背景网格）加 `aria-hidden`，不被读屏朗读
- 键盘焦点有 `:focus-visible` 描边
- 不隐藏系统光标（这条是刻意的：隐藏后点不准、看不清输入位置）
- 关闭 JS 时用 `<noscript>` 兜底，内容照常显示
